# Get support

Use [the guides](README.md) and [troubleshooting](guides/troubleshooting.md) first, then open a ticket for the part that remains unresolved.

## Choose the right route

| Request | Where to go |
| --- | --- |
| Something is broken | [Bug report](https://github.com/lukaluka/savorloop-community/issues/new?template=bug_report.yml) |
| Help using a screen or feature | [Usage question](https://github.com/lukaluka/savorloop-community/issues/new?template=help.yml) |
| An accessibility barrier | [Accessibility report](https://github.com/lukaluka/savorloop-community/issues/new?template=accessibility.yml) |
| A food record, nutrient display, or restriction behavior looks wrong | [Food-data report](https://github.com/lukaluka/savorloop-community/issues/new?template=food_data.yml) |
| A product improvement | [Feature request](https://github.com/lukaluka/savorloop-community/issues/new?template=feature_request.yml) |
| A security flaw or unintended exposure of data | [Private vulnerability report](SECURITY.md) |

GitHub issues are the ticket system. A GitHub account is required to submit or comment. There is currently no separate private general-support email or form.

## Before submitting

Search [existing issues](https://github.com/lukaluka/savorloop-community/issues). If the same problem already exists, add a useful reproduction detail or reaction instead of another ticket. Check [availability](guides/availability.md) to distinguish a current limitation from a broken feature.

Use one issue for one problem. Choose a descriptive title such as “Grocery check clears after reopening an unchanged plan.” Include the screen, numbered steps, expected result, actual result, app/build version if available, and device/OS version. Use “unknown” rather than guessing.

## Everything in an ordinary issue is public

Use fictional inputs. Do not upload a personal export, health history, body measurements, allergy profile, payment receipt, password, access token, identity document, or full diagnostic log. Crop and inspect screenshots before attaching them. A GitHub username and the content you submit may be visible to anyone.

Maintainers will not ask you to publish sensitive information to obtain help. If the problem cannot be described safely in public, ask a generic question about the support route without including private details. Use the private security channel only for suspected security issues.

## After submission

A maintainer may ask for a smaller reproduction, classify the issue, identify a duplicate, explain a current limitation, or link a fix. Reply in the existing ticket. Labels such as **needs-triage**, **needs-info**, and **confirmed** describe progress; they are not a delivery date or support contract.

You can close a ticket when resolved and explain what changed. If it returns in a later build, include that version and the new behavior. A closed ticket does not necessarily mean the fix has been distributed publicly.

No response-time guarantee or emergency service is offered. This channel cannot provide personal medical guidance, manage an Apple account, or recover a server copy of information that exists only on your device.

## If you accidentally post sensitive information

Edit or remove your exposed content promptly where GitHub permits it. Assume notifications or copies may already exist. Never post replacement credentials. Use GitHub's reporting tools for exposed private information and use the private security route if an app or repository vulnerability is involved. Deleting a comment does not guarantee recall of copies.
