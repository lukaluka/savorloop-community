# Security reporting

**Do not report vulnerabilities in public issues, comments, or pull requests.**

Use [Report a vulnerability](https://github.com/lukaluka/savorloop-community/security/advisories/new) to send a private GitHub report. This channel is for suspected security flaws affecting SavorLoop or this support repository, including unintended disclosure of local app information, unsafe data handling, or an exposed secret.

## What to include

- The affected component and app/build version, if known.
- A concise description of the suspected vulnerability and possible impact.
- Minimal reproduction steps using synthetic data and a device or environment you are authorized to test.
- Relevant redacted evidence and whether the issue is already publicly disclosed.

Start with the minimum information needed to understand the issue. Do not include real patient or user records, personal exports, passwords, private keys, payment information, or unnecessary identifying details, even in a private report.

## Scope and responsible handling

Please allow maintainers to assess the report before publishing exploit details. Do not access another person's information, disrupt a service, perform social engineering, or test systems you do not own or have permission to test. This policy does not grant authorization to test third-party services, provide a legal safe-harbor promise, or establish a paid bounty program.

The project is in development and does not yet publish a production support-version matrix. State the exact build you evaluated. Maintainers will assess reports against the current development implementation; no fixed response or remediation deadline is promised.

## Ordinary support and content moderation

Usage questions, feature requests, and non-security bugs belong in [support tickets](SUPPORT.md). Private vulnerability reporting is not a general private medical, billing, or account-support service. For abusive GitHub content, use GitHub's reporting controls; see [community guidelines](CODE_OF_CONDUCT.md).

If you cannot access the private reporting form, do not fall back to posting the exploit publicly. You may open a minimal issue saying the security-reporting link is unavailable, without disclosing vulnerability details or personal information.
